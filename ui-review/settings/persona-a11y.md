# Settings accessibility notes (keyboard and screen reader)

Opened from `#sys-menu-btn` then **Settings…** at http://127.0.0.1:8931/, viewport 1280×800. Erase was opened and cancelled only. Re-pull, Use latest, and Roll back were not activated. This Home Screen is already on the edge channel, so the edge row’s switch reads **Re-pull**, not “Load edge”.

1. **The Settings sheet is not a dialog, focus never enters it, and Escape does not close it.** Severity: High. What fails: `.modal.wide` is a plain `div` with no `role`, no `aria-modal`, no `aria-label`, and no `aria-labelledby`. The visible heading “Settings” is an `<h3>` and is not wired to the sheet. After the sheet opens, `document.activeElement` is `body`, not the name field or the heading. Escape leaves the sheet open (one `.modal.wide` before and after). Focus is not trapped. With the four disclosures closed, Tab from that starting point runs: name, background color, “Use a picture…”, Reset, “A−”, “A+”, Reset, summary “AI models”, summary “Third-party APIs”, summary “Payments”, summary “Advanced settings”, Save, Close — then leaves the sheet onto `body` and the GifOS menu button. Starting from the top of the page instead, Tab hits Invites, Add, fullscreen, the desktop, and in-page links (12 stops) before the name field. The page behind the sheet stays operable. Fix: make the sheet `role="dialog"` `aria-modal="true"` with `aria-labelledby` on the “Settings” heading, move focus to the name field on open, trap Tab and Shift+Tab inside the sheet, close on Escape, and set `inert` on the rest of the page. Screenshot: `a11y-03-settings-top.png`.

2. **Erase confirm has the same dialog gaps, and the first two Tab stops are not Cancel.** Severity: High. What fails: `#set-erase` removes the Settings sheet, then opens “Erase this entire computer?” as another plain `div.modal` (no role, no name, no description). Focus is on `body`, outside the confirm. Escape does not close it (modal count stayed 1). The first Tab lands on **Back up first, then erase**, the second on **Erase without backup** (`class="danger"`, no accessible description), the third on **Cancel**. The fourth Tab leaves the confirm for the GifOS button, then Invites and Add. Button names themselves are clear. Cancel does not restore Settings or return focus to “Erase this computer…”; focus ends on `body` and the sheet is gone. Fix: keep Settings mounted underneath, mark the confirm `role="alertdialog"` `aria-modal="true"` `aria-labelledby` the heading and `aria-describedby` the warning, move focus to Cancel, trap Tab, map Escape to Cancel, and on Cancel return focus to `#set-erase`. Screenshot: `a11y-20-erase-confirm.png`.

3. **Name, color, relay, AI fields, and API fields have no `<label>`, and the source and auth comboboxes have no name at all.** Severity: High. What fails: none of the 37 inputs or selects in the sheet has a `<label for>` or a wrapping `<label>`. The accessibility tree names them from placeholder or title only, so the visible headings (“Your name”, “Background”, “Smartest text LLM”, “Connection service”) are not the control names. Measured names: textbox “Your name”; color textbox “Background color” (from `title` only, no visible text on the swatch); seven textboxes “Base URL — e.g. https://api.openai.com/v1”; seven textboxes “API key”; model textboxes “Model — gpt-4o”, “Model — gpt-4o-mini”, “Model — tts-1”, and so on; textbox “short name — e.g. deepgram”; textbox “Base URL — e.g. https://api.deepgram.com”; textbox “Custom CORS proxy URL (optional — self-hosted)”; textbox “wss://relay.gifos.app”. Each AI source control is a combobox with an empty name (only the option “Your own endpoint (URL + key)”). The auth control is a combobox with an empty name. A screen-reader user in forms mode hears “API key” seven times and cannot tell Smartest text LLM from Speech → text. Fix: give every control a `<label>` whose text includes the row, for example “API key for Smartest text LLM” and “Source for Smartest text LLM”. Point the color input at a visible “Background color” label. Name the relay field “Connection service address”, not the example URL. Screenshot: `a11y-04-ai-models.png`, `a11y-15-api-test.png`.

4. **Test, Test & save, Test connection, and Repaint & measure results are not announced.** Severity: High. What fails: the status nodes have no `aria-live`, no `role="status"` or `role="alert"`, and no live ancestor. After Test on an empty AI row, `.ai-status` reads “Set a base URL first.” and stays silent to assistive tech. After Test & save on a blank API row, `.api-status` reads “give it a short name.” Test connection writes “Nothing to test — no address is set.” into `#set-relay-status`. Repaint & measure changes `#set-perf` from “14 icons in view · 11 reused, 3 rebuilt…” to “14 icons in view · 14 reused, 0 rebuilt…” with nothing announced. Fix: put `role="status"` and `aria-live="polite"` on `.ai-status`, `.api-status`, `#set-relay-status`, and `#set-perf`. Screenshot: `a11y-14-ai-test.png`, `a11y-15-api-test.png`, `a11y-17-relay-test.png`, `a11y-18-perf-after.png`.

5. **Version switches sit inside the disclosure, so its name includes Re-pull, Use latest, or Roll back.** Severity: Med. What fails: each version row’s `<button class="vbtn">` is inside `<summary>`. The edge disclosure’s accessible name is “Edge build build 0 RUNNING Re-pull” (`DisclosureTriangle`, `expanded: false`). The button’s own name is “Re-pull”. The same pattern puts “Use latest” or “Roll back” in the other summaries’ text. Keyboard users can open the notes without firing the switch: Tab lands on the summary first, Enter toggles it (edge row went from closed to open; channel and URL unchanged; the button never received a click), and the switch is the next Tab stop. What is broken is the nesting. The disclosure name advertises the version change, the caret is `aria-hidden`, and the very next key is the switch. Fix: move Re-pull, Use latest, and Roll back out of `<summary>` so the disclosure name is only the version label, and keep the button as the next sibling. Screenshot: `a11y-12-version-edge.png`.

6. **Text-size buttons are named “A−” and “A+”, and the percentage is not announced.** Severity: Med. What fails: `#ts-minus` has accessible name “A−” (`title="Smaller"` is not the name). `#ts-plus` is “A+” (`title="Bigger"`). `#ts-val` is static text “100%” with no `aria-live`. Activating A+ changes it to “110%” and nothing is announced; Reset returns “100%”, also silent. Fix: name the buttons “Decrease text size” and “Increase text size” (keep the visible “A−” / “A+” in the name or mark the glyph `aria-hidden`), and set `aria-live="polite"` on `#ts-val`. Screenshot: `a11y-11-text-size.png`.

7. **Every password reveal control is named “Show password”, with an unnamed icon inside.** Severity: Med. What fails: eight eye buttons (seven AI keys plus the API key on the row added in this pass) expose `aria-label="Show password"`. None has `aria-controls`, `aria-pressed`, or the row name. The tree is `button "Show password"` containing an `img` because the SVG is not `aria-hidden`. After the first eye is toggled, that button’s name becomes “Hide password” and the field stays a textbox “API key”; the other seven stay “Show password”. A screen-reader user cannot tell which key will be revealed. Fix: `aria-label="Show API key for Smartest text LLM"` (and “Hide…” when revealed), `aria-pressed`, `aria-controls` pointing at that input, and `aria-hidden="true"` on the SVG. Screenshot: `a11y-16-password-eye.png`.

8. **“LATEST” fails AA. Muted help and the disclosure summaries pass.** Severity: Med. What fails: the latest pill is white `#ffffff` on `color(srgb 0.159059 0.608706 0.272235)` (about `#299b45`), 10.56px, weight 700. Contrast is **3.57:1**. That size is normal text, so the AA bar is 4.5:1, not the 3:1 large-text bar. The running pill passes at **4.70:1** (`#0071e3` on `#ffffff`, same 10.56px bold). Sampled as requested, and these pass AA: `.add-help` is `#6e6e73` on `#ffffff`, 14.4px, weight 400, **5.07:1**; a closed disclosure summary (“AI models”, “Third-party APIs”, “Payments”, “Advanced settings”) is the same `#6e6e73` on `#ffffff`, 13.6px, weight 400, **5.07:1**; an open summary and the “Erase this computer” summary (once Advanced settings is open) are `#1d1d1f` on `#ffffff`, **16.83:1**. Close uses the same muted gray at **5.07:1** and passes. Fix: darken the LATEST green or use dark text on it until the badge text is at least 4.5:1. Leave the passing muted help and summaries alone. Screenshot: `a11y-12-version-edge.png`.

9. **The GifOS menu does not take focus, so Settings… is not the next stop.** Severity: Med. What fails: Enter on `#sys-menu-btn` opens the menu (About GifOS, App Store…, Arrange icons…, Back up Home Screen…, Restore from backup…, Empty Trash, Settings…) but focus stays on the GifOS button. The menu is a `div.ctx` with no `role` and no label. The next 12 Tab stops are Invites, Add, fullscreen, the desktop, and page links. Settings… is not among them. It is a plain button appended at the end of the page, after that content. Fix: on open, move focus to the first item, use `role="menu"` and `role="menuitem"`, keep keyboard movement inside the menu, and close it on Escape. Screenshot: `a11y-02-menu.png`.
